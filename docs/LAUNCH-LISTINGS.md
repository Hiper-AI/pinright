# Launch listings

Ready-to-paste submissions for the directories where people find MCP servers. Nothing here has
been submitted. Checked against each directory's docs on 2026-11-01; they change often, so re-read
the linked page before submitting.

Names used below: npm package `pinright`, MCP Registry name `io.github.Hiper-AI/pinright`,
repository `https://github.com/Hiper-AI/pinright`. After a rename, run `npm run dist:artifacts`
and replace the name in this file.

## Descriptions

Short, 100 characters at most (the MCP Registry limit). It is `SHORT_DESCRIPTION` in
`scripts/distribution.ts`, which also feeds `server.json` and the `.mcpb` manifest:

> Version-accurate library docs for coding agents, with a supply-chain check of each dependency.

Paragraph, for directories with a longer field:

> pinright is a local MCP server and pre-install hook for coding agents. When the agent asks for
> library docs, pinright reads them from the package at the version the project uses (published
> files, the repository at the release tag, llms.txt), so the agent writes code for that version.
> Before the agent adds a dependency, pinright checks it against OSV and deps.dev: known
> advisories, malware records, deprecation, lookalike names and versions that do not exist. It
> suggests the newest version without known advisories, on the release line the project already
> uses when there is one. The hook works in Claude Code, Cursor, VS Code (Copilot), Codex, Gemini
> CLI and Windsurf and can stop the install before it runs. Runs on your machine over stdio, no
> account, no telemetry; MIT.

Tools, for directories that list them:

| Tool | One line |
|---|---|
| `find-library` | Library name to registry package, with the safe version and a verdict |
| `get-docs` | Docs sections for a question, from the package at a given version |
| `upgrade-guide` | What changes between two versions, and the advisories the move fixes |
| `check-packages` | Verdict for up to 50 packages in one call |
| `check-package` | Full verdict for one package |
| `check-manifest` | Whole-tree audit of a lockfile or manifest |

Keep the claims to what the code does. pinright checks known advisories and the signals listed in
the README; it does not find unknown vulnerabilities, and a package with no known advisory is not
proven safe. Avoid "secure", "100%", "guaranteed", "eliminates", "zero-day".

Categories and tags, where a directory asks: Security; Developer Tools. Tags: `supply-chain`,
`dependencies`, `documentation`, `npm`, `pypi`, `osv`, `coding-agents`.

## 1. Official MCP Registry

- Page: https://registry.modelcontextprotocol.io. Docs:
  https://github.com/modelcontextprotocol/registry/tree/main/docs/modelcontextprotocol-io
- Artifact: `server.json` at the repository root, generated by `npm run dist:artifacts` and checked
  against the 2025-12-11 schema by `test/distribution.test.ts`. Its `version` and
  `packages[0].version` must equal the npm version you published.
- Name: `io.github.Hiper-AI/pinright`. The registry builds the allowed namespace from the GitHub
  org login without changing its case, so it stays `Hiper-AI`.
- Ownership: `mcpName` in the published `package.json` equals `name` in `server.json`.

Steps, from the repository root on the 1.0.0 tag (PowerShell):

```powershell
git checkout v1.0.0
$arch = if ([System.Runtime.InteropServices.RuntimeInformation]::ProcessArchitecture -eq "Arm64") { "arm64" } else { "amd64" }
Invoke-WebRequest -Uri "https://github.com/modelcontextprotocol/registry/releases/latest/download/mcp-publisher_windows_$arch.tar.gz" -OutFile "$env:TEMP\mcp-publisher.tar.gz"
tar xf "$env:TEMP\mcp-publisher.tar.gz" -C "$env:TEMP" mcp-publisher.exe
& "$env:TEMP\mcp-publisher.exe" validate
& "$env:TEMP\mcp-publisher.exe" login github      # device code; authorize as a member of Hiper-AI
& "$env:TEMP\mcp-publisher.exe" publish
```

On macOS or Linux: `brew install mcp-publisher`, then the same three commands.

Check:

```bash
curl -s "https://registry.modelcontextprotocol.io/v0.1/servers?search=io.github.Hiper-AI/pinright"
```

returns the entry with version 1.0.0. If `login github` refuses the namespace, the org membership
is private: make it public on https://github.com/orgs/Hiper-AI/people, or ask an org owner to publish.

## 2. Glama

- Directory: https://glama.ai/mcp/servers. Glama lists public GitHub repositories and grades
  license, quality and maintenance. It can run the server in Docker for its checks; the server
  starts with no configuration (`npx -y pinright`) and needs outbound HTTPS to the services in
  SECURITY.md to answer.
- Claiming a repository under an organization takes a `glama.json` at the root
  (https://glama.ai/blog/2025-07-08-what-is-glamajson). Add it on `main` once the maintainers
  are decided; with the code owner today it is:

  ```json
  {
    "$schema": "https://glama.ai/mcp/schemas/server.json",
    "maintainers": ["juanmandelbaum"]
  }
  ```

- Submit: on the directory page, "Add Server", paste `https://github.com/Hiper-AI/pinright`. Glama
  fills name and description from the repository; use the paragraph above if it asks.
- Check: `https://glama.ai/mcp/servers/Hiper-AI/pinright` loads, and the score badge
  `https://glama.ai/mcp/servers/Hiper-AI/pinright/badges/score.svg` renders. awesome-mcp-servers
  needs that badge.

PulseMCP takes no direct submissions; it picks servers up from the Official Registry

`https://www.pulsemcp.com/servers?q=pinright`. If the entry is missing after a week, write to the
contact address on the submit page with the registry name `io.github.Hiper-AI/pinright`.

## 4. Smithery

- Smithery takes local stdio servers as a prebuilt MCPB bundle, not as a `smithery.yaml` build
  (https://smithery.ai/docs/build/publish).
- Build the bundle from the release tag: `npm run build:mcpb` writes
  `build/mcpb/pinright-1.0.0.mcpb`. It validates the manifest against the MCPB 0.3 schema and with
  `@anthropic-ai/mcpb`. The bundle is unsigned; `mcpb sign` needs a certificate.
- Publish: `npx -y @smithery/cli mcp publish ./build/mcpb/pinright-1.0.0.mcpb -n hiper-ai/pinright`
  (logged in to Smithery; check the CLI's current syntax with `--help` first).
- Fields Smithery shows come from the manifest: display name `pinright`, description
  `SHORT_DESCRIPTION`, the tools the built server reports. Add the paragraph above as the long
  description in the Smithery UI if it asks.
- Check: `https://smithery.ai/server/hiper-ai/pinright` loads and lists six tools.

## Install links

The "Install links" block in `docs/install.md` (Cursor and VS Code buttons) is generated from `package.json` by
`scripts/distribution.ts`. GitHub does not link `cursor://` or `vscode:` URLs, so the buttons go
through `https://cursor.com/en/install-mcp` and `https://insiders.vscode.dev/redirect`.
