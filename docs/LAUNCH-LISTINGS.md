# Launch listings

Drafts and requirements for the directories where MCP servers get found. Nothing here has been
submitted. Checked against each directory's docs on 2026-10-29; they change often, so re-read the
linked page before submitting.

Everything below assumes the final npm name. Today that name is `pinright` and the registry name is
`io.github.Hiper-AI/pinright`. After a rename, run `npm run dist:artifacts` and replace the name in
the drafts below.

## Before any listing

- [ ] Final name decided (`docs/RELEASE.md`, step 1), `package.json` updated, `npm run dist:artifacts` run.
- [ ] Repository public. Glama and awesome-mcp-servers only take public GitHub repositories.
- [ ] Package published to npm (`docs/RELEASE.md`). The MCP Registry checks `mcpName` in the
      published `package.json`, so the registry entry comes after the npm release.
- [ ] A 400x400 PNG logo (the Cline Marketplace asks for one; the `.mcpb` can carry `icon.png`).

## Descriptions

One line, 100 characters at most (the MCP Registry limit). It is `SHORT_DESCRIPTION` in
`scripts/distribution.ts`, which also feeds `server.json` and the `.mcpb` manifest:

> Version-accurate library docs for coding agents, with a supply-chain check of each dependency.

Paragraph, for directories with a longer field:

> pinright is a local MCP server and pre-install hook for coding agents. When the agent asks for
> library docs, it reads them from the package at the version the project uses (published files,
> the repository at the release tag, llms.txt), so the agent writes code for that version. Before
> the agent adds a dependency, pinright checks it against OSV and deps.dev: known advisories,
> malware records, deprecation, lookalike names and versions that do not exist, and it suggests
> the newest version without known advisories, on the release line the project already uses when
> there is one. The hook works in Claude Code, Cursor, VS Code (Copilot), Codex, Gemini CLI and
> Windsurf and can stop the install before it runs. Runs on your machine over stdio, no account,
> no telemetry; MIT.

Keep the claims to what the code does. It checks known advisories and the signals listed in the
README; it does not find unknown vulnerabilities, and a package with no known advisory is not
proven safe. Avoid "secure", "100%", "guarantees", "zero-day".

## Official MCP Registry

- Page: https://registry.modelcontextprotocol.io, repo https://github.com/modelcontextprotocol/registry
- Artifact: `server.json` at the repository root, generated by `npm run dist:artifacts` and checked
  against the 2025-12-11 schema by `test/distribution.test.ts`.
- Name: `io.github.Hiper-AI/<name>`. The registry builds the allowed namespace from the GitHub org
  login without changing its case, so it must stay `Hiper-AI`, not `hiper-ai`.
- Ownership: `mcpName` in `package.json` must equal the `name` in `server.json`
  ([package types](https://github.com/modelcontextprotocol/registry/blob/main/docs/modelcontextprotocol-io/package-types.mdx)).
- Steps, after the npm release: install `mcp-publisher` from the registry's GitHub releases, then
  `mcp-publisher validate`, `mcp-publisher login github` (as a member of the Hiper-AI org), and
  `mcp-publisher publish`. Bump `version` in `package.json` and rerun `dist:artifacts` for each release.
- PulseMCP does not take submissions now and says it picks servers up from the Official Registry
  (https://www.pulsemcp.com/submit).

## Claude Desktop extension (.mcpb)

- Build: `npm run build:mcpb` writes `build/mcpb/<name>-<version>.mcpb`. It validates the manifest
  against the MCPB 0.3 schema and with `@anthropic-ai/mcpb` (pinned in `scripts/build-mcpb.ts`).
- The bundle is unsigned. `mcpb sign` needs a certificate; decide before distributing it.
- Spec: https://github.com/modelcontextprotocol/mcpb (MANIFEST.md).

## Smithery

- Smithery takes local stdio servers as a prebuilt MCPB bundle, not as a `smithery.yaml` build
  (https://smithery.ai/docs/build/publish). The `.mcpb` above is the artifact.
- Command, when the time comes: `smithery mcp publish ./build/mcpb/<name>-<version>.mcpb -n hiper-ai/<name>`.
- Smithery shows the manifest's description and tools; they come from `scripts/distribution.ts`
  and from the tools the built server reports.

## Glama

- Glama lists GitHub repositories and grades license, quality and maintenance
  (https://glama.ai/mcp/servers). A repository under an organization is claimed with a
  `glama.json` at the root (https://glama.ai/blog/2025-07-08-what-is-glamajson):

  ```json
  { "$schema": "https://glama.ai/mcp/schemas/server.json", "maintainers": ["<github-username>"] }
  ```

  Add it with the real GitHub usernames of the maintainers when the repository goes public; it is
  not in the repository yet because the usernames are not decided.
- Glama can run the server in Docker for its checks. The server needs no configuration to start
  (`npx -y <name>`), and it needs outbound HTTPS to the services in SECURITY.md to answer.

## Cline Marketplace

- Submission: a GitHub issue at https://github.com/cline/mcp-marketplace with the repository URL,
  a 400x400 PNG logo and why it belongs there. Cline must be able to install it from the README;
  an `llms-install.md` is optional. The README's Cline block covers the install.

## Install links

The README's "Install links" block (Cursor and VS Code buttons) is generated from `package.json` by
`scripts/distribution.ts`. GitHub does not link `cursor://` or `vscode:` URLs, so the buttons go
through `https://cursor.com/en/install-mcp` and `https://insiders.vscode.dev/redirect`.
